# Static parameter binding checkpoint

Incoming parameters now receive their frame locations during checking. The
native emitter consumes that location directly instead of rebuilding and
searching a parameter-name map. Lexical shadowing, destructuring, closure
captures and tail re-entry retain their existing contracts.

## Recorded validation

The qualification receipt records 779 passing tests. The separate corpus
comparison covers 404 cases (284 accepted and 120 rejected). Native rebuild
receipts establish self-hosting reproducibility. Failed test attempts and the
subsequent assertion corrections are retained rather than discarded.

Current source hashes were rechecked against the qualification receipt before
this checkpoint was committed. This check did not rerun the full suite.

## Measurements and limits

One instrumented invocation of the actual parameter-expression emitter executed
455 instructions before and 178 after, including nested calls but excluding
its driver. That is one bounded compiler path, not a whole-program result or
a hardware-cycle measurement.

Nine paired whole-compiler samples recorded median CPU time of 0.489733 seconds
before and 0.481986 after (about 1.6% lower). Sample ranges overlap on the shared
host; this is a small observed change, not an established broad speedup.
Maximum peak RSS was 205,056 versus 205,312 KiB. Hardware performance counters
were unavailable.

The corpus retained identical generated bytes and rejection diagnostics. That
supports preservation for these cases; it does not demonstrate optimization of
the programs being compiled. Further optimization remains open.
